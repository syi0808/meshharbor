# Semantic repart feasibility

**Decision:** prototype guided separation with GeoSAM2. It can label meaningful regions inside a single connected mesh, but a label is not a cut, a complete part, or a joint. No AI repart backend is shipped. The previous connected-component operation has been retired; its saved outputs and job history remain readable.

[HoloPart](https://github.com/VAST-AI-Research/HoloPart) has [MIT-tagged weights](https://huggingface.co/VAST-AI/HoloPart) and can generate missing surfaces after an initial segmentation. Treat it as optional geometry completion, not reliable recovery of hidden geometry or original textures. [Hunyuan3D-Part](https://github.com/Tencent-Hunyuan/Hunyuan3D-Part) also provides segmentation and completion, but its [published license](https://github.com/Tencent-Hunyuan/Hunyuan3D-Part/blob/main/LICENSE) excludes South Korea, the EU, and the UK from its territory.

## Apple Silicon probe

On an Apple M3 Pro (macOS 26.2, Python 3.12, PyTorch 2.15), the pinned GeoSAM2 checkpoint ran on MPS in an isolated environment. The unmodified setup failed first: Apple Clang rejected the CPU label-voting extension's OpenMP flag, and the OpenCV 5.1 macOS wheel had no EXR decoder. The probe compiled that helper in serial and decoded the existing depth images with the Python OpenEXR package. It verified the 616 MB FP32 checkpoint SHA-256 as `2e391c0d9455fe92b69d61cdc94754d9b8081b9b541d09e1b6a3a55ebf6c6de0` and loaded weights only.

The upstream `sample_00` includes 12 rendered views and example click prompts. Of 407,657 triangles, 407,643 were in its largest edge-connected group after matching exactly coincident positions. The raw propagation path (without optional opposite-view automatic masks or label refinement) produced 20 distinct nonzero labels within that one group; 92,343 faces across the asset had label zero. This demonstrates labels cutting across existing connectivity, not complete or accurate partitioning. MeshHarbor imported the preview with all 407,657 triangles, but it contained only one primitive with vertex colors in place of the original texture. The source and preview triangle-coordinate arrays did not match row for row, so a direct index mapping is not established.

This probe did not render a new asset, assess part quality or joint motion, or validate an installable runtime. No upstream code or weights were added to the product.

## Integration boundary

1. Start with one static, embedded, indexed triangle GLB and a rigid object with one intended moving part, such as a door or lid. Let the user select that part and correct the boundary before committing anything; do not silently fall back to grouping disconnected pieces.
2. Run segmentation in an isolated local worker. Pin the code, dependencies and checkpoint digest, require explicit installation, and keep inference offline. For the first prototype, stage the input and preserve original triangle IDs through the renderer and importer. Reject mismatched face counts or out-of-range/ambiguous face correspondence rather than trusting the preview GLB's ordering.
3. Build independently transformable scene nodes in a new GLB using those original faces and their material and UV streams. A preview that only colors the original surface is not a successful export. Cap exposed boundaries only when the result validates; filling real hidden geometry is a separate problem. Studio's existing same-mesh UV rebake cannot recover an original texture for a face that did not exist.
4. Let the user set a joint axis and pivot (or sliding direction) and limits in the first prototype. Export a test animation and keep the source revision intact. Studio currently loads the static scene for preview, so animation playback needs new support. Smoothly bending characters need a separate skeletal-rigging workflow.

The shipping gate is a successful fresh install and a representative set of known fused GLBs: check part boundaries, material/UV retention at rest, exposed surfaces and collisions over the expected motion, and editable nodes and animation on Blender reimport. Validate Apple Silicon and Linux/NVIDIA separately; no performance target or implicit model availability follows from one upstream example.
