# Licensing and dependency status

The first-party code and documentation in this version of MeshHarbor are licensed under the [Elastic License 2.0](../LICENSE), a source-available license. That license does not cover third-party material; see the [notice index](../THIRD-PARTY-NOTICES.md). This audit records known terms and open questions. It is not a redistribution or commercial-use approval for the complete repository, model runtimes, or a future release.

## Rust application dependencies

The current `Cargo.lock` resolves the Rust workspace dependency graph. A `cargo metadata --locked --format-version=1` inventory found no third-party package missing both `license` and `license_file` metadata in the default resolution. Most packages state MIT, Apache-2.0, or both. Some require selection or preservation of additional terms: `foldhash` is Zlib; `matchit` is MIT AND BSD-3-Clause; `ryu` allows Apache-2.0 OR BSL-1.0; `r-efi` offers MIT, Apache-2.0, or LGPL-2.1-or-later. Metadata is not a review of the license texts or the target-specific dependency closure. A complete release SBOM, binary notices, and legal review are pending.

The mesh simplifier uses `meshopt` 0.7.0 (`MIT OR Apache-2.0`), which wraps/builds upstream meshoptimizer (`MIT`). The dependency graph is in `Cargo.lock`; it includes no model weights.

The optional `remesh` 0.0.5 crate (`MIT OR Apache-2.0`) is a separate isotropic triangle-remesher prototype, not QuadriFlow and not dispatched by `mesh.retopology`. It remains outside the active operation path; its transitive license inventory still needs review before any use. See [the candidate scope](retopology-candidate.md).

## Vendored Pixal3D source snapshots

The two source repositories were copied as pinned, file-by-file snapshots, not reduced to helper-only subsets:

- CUDA `syi0808/pixal3d-cuda` at `a4cb2b226cdb2bf3328eb280d4a02e510cc78e8c`: 56 of 59 Git blobs preserved; 3 generated historical evidence files omitted.
- MLX `syi0808/pixal3d-mlx` at `3a832ebf5f346a7eafb1ba40ca2926cfbd0bb2d6`: 150 of 189 Git blobs preserved; 37 image/GLB assets and 2 generated witness records omitted because asset rights/provenance are unverified.

Every preserved local file was compared against its pinned upstream Git blob hash. Paths, hashes, sizes, and reasons for all exclusions are recorded in [`pixal3d-source-inventory.json`](pixal3d-source-inventory.json). Each source root retains the full upstream MIT `LICENSE` naming Noah Lyons. That license does not automatically clear every credited or derived component. The referenced projects' license copies and source-attribution notes are in [`runtimes/pixal3d/THIRD-PARTY-NOTICES.md`](../runtimes/pixal3d/THIRD-PARTY-NOTICES.md) and `runtimes/pixal3d/THIRD-PARTY-LICENSES/`.

Known third-party conditions remain distinct from the port repositories' MIT notices:

- DINOv3-related source is accompanied by Meta's custom [DINO Materials Agreement](../runtimes/pixal3d/THIRD-PARTY-LICENSES/DINOv3-LICENSE.md). It is not MIT; covered source and derivatives retain that agreement on redistribution, including when embedded in an executable. Confirm the covered file scope and compliance separately from gated weight access.
- NAF-related code is accompanied by Apache-2.0 terms; the commercial inference scope for the exact NAF release checkpoint remains unresolved upstream.
- MoGe code is accompanied by the upstream MIT/Apache-2.0 license file. The CUDA source pins a MoGe model revision separately.
- TRELLIS.2-related code retains Microsoft's MIT notice. Other credited MIT port licenses are also preserved, without claiming all source lineage has been legally adjudicated.
- The MLX tree includes source for a CGAL bridge, but not CGAL headers, library, or binary. Building/distributing an executable that uses CGAL needs a separate GPL-3.0-or-later or commercial licensing decision.

The Rust executable embeds the CUDA and MLX source snapshots and their managed adapters, not model weights, credentials, Python wheels, or user assets. Setup can bootstrap pinned uv. The Linux x86_64/NVIDIA CUDA profile resolves upstream dependency ranges into a per-install lock; it has no committed lock or fresh end-to-end GPU acceptance run for this snapshot. [MLX setup and offline inference passed on one Apple Silicon Mac](pixal3d-mlx-manual-runtime.md#validation-status), using existing large checkpoints. That does not establish broader hardware, output-quality, or licensing clearance. Model downloads are separate and require explicit confirmation and any applicable gated access.

For runtime and checkpoint review, track at least:

- DINOv3 license and gated weight access, and the applicable Tencent Pixal3D model/checkpoint terms.
- NAF checkpoint commercial-use scope ([upstream issue #13](https://github.com/valeoai/NAF/issues/13)).
- Any change that enables background removal: the managed MLX profile currently disables `rembg` inference. If enabled, verify the selected model independently of the Python package license.
- Complete native/Python dependency notices and the OS/accelerator support matrix. The managed MLX profile uses fan hole filling; review CGAL's linked-binary terms separately before enabling the dormant bridge.
- Any generated web bundle: `web/vendor.mjs` is source only; if run, its generated `@google/model-viewer` bundle is Apache-2.0 and needs corresponding notices. No bundle is present here.

## QuadriFlow sidecar candidate

The [opt-in linked build](retopology-candidate.md#linked-development-build) compiles a pinned external QuadriFlow checkout into the executable. It does not change the default build or approve redistribution. No upstream QuadriFlow source or binary is copied into the MeshHarbor tree. The rest of this section covers the managed-sidecar path, which is unavailable in the default build. Runtime code no longer searches beside the MeshHarbor executable and never auto-executes an adjacent `quadriflow` file. A managed executable can become ready only after an in-process verifier accepts release signature/provenance and its SHA-256 matches the trusted bundled manifest. The in-process verifier is integrated, but the checked-in manifest is empty and no approved sidecar is listed, so managed readiness, installation, and rollback remain fail-closed. The temporary candidate run [#43721747855](https://github.com/syi0808/meshharbor/actions/runs/43721747855) completed the three platform build-pair, signing, and candidate-verification gates. Linux and macOS then executed their exact signed candidates against the synthetic geometry-only cube and passed MeshHarbor core's quad-output validator ([Linux job](https://github.com/syi0808/meshharbor/actions/runs/43721747855/job/132848222187), [macOS job](https://github.com/syi0808/meshharbor/actions/runs/43721747855/job/132848222186)). The original Windows native job failed its SLSA-material check before executing; the same original Windows artifact was later reverified and smoke-executed against a synthetic cube in the read-only [run #43731453754](https://github.com/syi0808/meshharbor/actions/runs/43731453754), without a MeshHarbor core output-validator step. These geometry-only checks do not test textured appearance or enable product installation. This also prevents a crafted activation marker from self-authorizing its own executable hash. Studio, CLI, REST, and MCP do expose backend status and an install request; Studio keeps the button disabled and the API/CLI reject installation before network downloads or QuadriFlow backend-directory writes. The manual candidate verifier is maintainer-only and is not connected to product installation. The candidate source is pinned to `hjwdzh/QuadriFlow` commit `810b7a0967c35b0dc85b4464e3835e26a756c967`. Its `LICENSE.txt` contains BSD-style three-clause terms plus an additional grant for publicly available enhancements, despite the README's MIT description.

The build smoke uses `BUILD_FREE_LICENSE=ON` (which selects Eigen's `EIGEN_MPL2_ONLY` path) and disables TBB, OpenMP, Gurobi, and Lemon's GLPK, ILOG, COIN, and SoPlex backends. Reviewed bundled components include Lemon under Boost Software License 1.0 and pcg32 under Apache-2.0. These settings and notices do not constitute complete dependency/SBOM clearance or a redistribution approval. In candidate run [#43721747855](https://github.com/syi0808/meshharbor/actions/runs/43721747855), signed temporary Actions ZIPs were configured for one-day retention; verification and smoke-evidence artifacts were configured for seven days. The Windows-only follow-up [#43731453754](https://github.com/syi0808/meshharbor/actions/runs/43731453754) reused the exact original signed artifact and did not sign or publish a new candidate. These retention periods apply to temporary Actions artifacts, not product installers or releases. The earlier synthetic smoke artifacts were temporary and are also not product installers. The current artifact collector copies notice files found in the pinned QuadriFlow source tree but does not collect package-manager license texts for installed dependencies (vcpkg, Homebrew, or apt), so the smoke archives are not complete third-party notice bundles. Preserve the upstream and third-party notices and obtain a full per-platform dependency review before shipping any binary.

The offline `scripts/quadriflow_notices.py` helper now collects only an explicit, caller-supplied package/notice inventory and emits preserved notice files, an index, an SPDX 2.3-shaped SBOM, and checksums. It always marks `release_ready=false` and `dependency_closure_verified=false`; it does not discover the full binary dependency graph, run an external SPDX validator, prove the pinned checkout, or make a legal conclusion. Complete per-platform notice closure and release review are still pending, and the existing smoke artifacts are not inputs to the manifest.

The [retopology candidate report](retopology-candidate.md) records the platform-by-platform smoke status and evidence artifact checksums. QuadriFlow itself receives geometry-only OBJ input. MeshHarbor can optionally project only supported embedded base-color/metallic-roughness PNG maps onto the triangulated GLB preview after the sidecar returns; the editable quad OBJ remains geometry-only. This candidate texture path is fail-closed but has no real-asset fidelity certification.
